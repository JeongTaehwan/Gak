# 요구사항

> 상태: 프로젝트 오너 승인 완료 — 입력 화면(4절 개정 포함) · 통합 타임라인 (2026-08-20).

## 입력 화면

### 1. 화면이 답하는 질문

- 사용자는 선택한 팀이 왜 부진한지, 어떤 선수가 문제인지 자유롭게 묻는다.
- 모든 자유 질문은 진단 경로로 보낸다.
- 질문 처리 경로는 `teamId`와 `season`을 반드시 함께 받는다.
- 답변은 해당 팀·시즌의 계산된 진단 데이터만 근거로 작성한다.
- 뉴스와 소문은 진단 근거로 사용하지 않는다.
- 예측이나 화면 이동으로 보내는 분기는 만들지 않는다.
- 데이터로 답할 수 없는 질문은 억지로 답하지 않고 원인별 상태를 표시한다.

### 2. 출시 단계와 팀 선택

#### 1차 비공개 검증

- 프로젝트 오너만 사용한다.
- 맨체스터 유나이티드(API-Football 팀 ID 33)만 다룬다.
- 팀 선택 UI를 노출하되 선택 가능한 팀은 맨체스터 유나이티드 하나다.
- 일반 사용자에게 공개하지 않는다.

#### 공개 버전

- 다팀 선택까지 완료한 뒤 일반 사용자에게 공개한다.
- 선택 가능한 팀 목록은 저장하지 않고 경기 데이터에서 파생 계산한다.
- 선택 가능한 팀은 조회 시즌에 선택 기준 대회의 경기가 있는 팀이다.
- 선택 기준 대회는 프리미어리그(39), 라리가(140), 분데스리가(78), 세리에 A(135), 리그 1(61), K리그1(292)이다.
- 시드에는 어떤 대회가 선택 기준인지 여부만 저장하고 팀 목록은 저장하지 않는다.
- 컵·유럽대항전 참가 여부와 `competition.displayed`는 팀 선택 기준으로 사용하지 않는다.
- 동기화 대상 대회와 선택 기준 대회는 서로 다른 개념이다.
- `team` 테이블의 805개 팀을 선택 목록으로 그대로 노출하지 않는다.
- 선택 가능 팀은 조회 중인 시즌을 기준으로 판정한다.
- 과거 시즌을 조회하면 그 시즌에 선택 기준 대회 경기가 있던 팀이 선택 대상이다.
- 입력 화면과 아래 네 화면은 이 파생 규칙을 공유한다.

### 3. 시즌과 회고

- 현재 시즌은 `AnalysisPeriodResolver`가 치른 경기가 있는 시즌 중 가장 큰 `season`으로 자동 판정한다.
- URL의 `season`은 자동 판정 당시의 시즌을 고정한다.
- 같은 URL은 시간이 지나도 같은 시즌을 재현한다.
- URL의 시즌을 기준으로 선택 가능 팀을 다시 계산한다.
- 통합 타임라인·진단·예측/적중 기록·순위표는 URL의 같은 시즌을 사용한다.
- 이전 시즌 진입점은 `지난 시즌 보기` 버튼 하나다.
- 시즌 드롭다운과 시즌 목록 화면은 만들지 않는다.
- 버튼을 누르면 현재보다 작은 조회 가능 시즌 중 가장 큰 값으로 이동한다.
- 조회 가능 시즌은 선택 기준 대회 6개 중 하나라도 경기 데이터가 있는 시즌이다.
- 더 오래된 조회 가능 시즌이 없으면 버튼을 비활성화하고 `이전 시즌 데이터가 없습니다`라고 표시한다.
- 과거 시즌에서는 `다음 시즌 보기`로 한 시즌씩 앞으로 이동한다.
- 자동 판정 최신 시즌에 도달하면 현재 시즌임을 표시하고 다음 시즌 이동을 제공하지 않는다.
- 시즌을 이동해도 선택한 팀을 유지한다.

### 4. 조회 시즌에 선택 기준 리그 기록이 없는 팀

- 팀을 다른 팀으로 바꾸거나 선택을 비우지 않는다.
- `이 시즌에는 선택 대상 1부 리그 기록이 없습니다`라고 표시한다.
- 선택 기준 대회 기록이 없다는 사실만으로 2부·3부 소속이나 동기화 누락 여부를 단정하지 않는다.
- 컵 경기만 존재하면 통합 타임라인은 부분 데이터임을 밝히고 컵 경기만 표시한다.
- (2026-08-20 개정) 위 컵 경기만 존재하는 경우는 선택 자격 규칙(IN-OQ-02: 조회 시즌에
  선택 기준 대회 경기 존재)에 의해 정상 진입으로는 도달 불가한 경우다. URL 직접 진입 등
  비정상 경로에 대한 방어 동작으로 유지한다.
- 선택 기준 리그 경기 없이 진단하지 않고 `판정 불가`로 표시한다.
- 예측/적중 기록은 조회 시즌 기록만 표시하고 없으면 해당 시즌 기록 없음으로 표시한다.
- 순위표는 표시하지 않으며 최신 시즌 순위표로 대체하지 않는다.
- URL의 `teamId`가 그 시즌의 선택 대상이 아니어도 다른 팀으로 조용히 대체하지 않는다.

### 5. 질문 입력과 답변 상태

- 가이드 질문 버튼과 자유 입력을 함께 제공한다.
- 특정 선수가 문제라는 결론은 근거 데이터가 있을 때만 제시한다.
- 답변할 수 없을 때 근거 데이터 부족·지원 범위 밖·분석 처리 실패·질문 이해 실패를 구분한다.
- 상태별 최종 문구는 `[미정]`이다.
- 팀 목록 로딩·팀 목록 실패·선택 가능 팀 없음·질문 처리 중 상태의 화면 표현은 `[미정]`이다.

### 6. URL과 상태 복원

- URL은 선택한 팀, 고정된 대상 시즌, 현재 탭을 기록한다.
- 새로고침하거나 URL을 공유했을 때 같은 팀·시즌·탭을 복원한다.
- 구체적인 URL 경로와 파라미터 형식은 `[미정]`이다.

### 7. 이번 범위 밖

- 통합 타임라인·진단·예측/적중 기록·순위표의 상세 동작
- 이전 시즌 회고록의 상세 내용(`[미정]`)
- 예측·순위표 완성 후 자유 질문 분류기 도입 여부

입력 화면에서 정한 `teamId + season`을 아래 화면과 질문 처리 경로에 일관되게 전달하는 계약은 이번 범위에 포함한다.

## 통합 타임라인 (TL)

### 1. 화면이 답하는 질문

- "리그 일정만 보면 여유로워 보이는 팀이, 전 대회를 합치면 밀집 구간에 있다"는 대비를
  사용자가 이 화면에서 직접 확인한다.
- 입력 화면에서 확정된 `teamId + season`으로 진입한다. URL의 시즌 고정 규칙은
  입력 화면 3절의 계약을 따른다.
- 그 팀·해당 시즌의 경기를 리그·컵·유럽대항전 구분 없이 하나의 시간축에 그린다.
- 회고(과거) 시즌에서도 동일하게 동작한다.

### 2. 시간축

- 시즌 전체를 한 화면에 조망하는 방식으로 그린다.
- 구간 확대·이동 상호작용의 제공 여부와 방식은 `[미정]`이다.
- 과거 경기와 미래 경기가 한 축에 섞인다. 치른 경기와 예정 경기의 경계 표시는
  기존 계약(`inAnalysis`)을 따른다.
- 미래 경기 구간의 시각적 표현은 `[미정]`이다.

### 3. 밀집 구간

- 판정 기준: **임의의 14일 창 안에 5경기 이상**이면 밀집이다(창 폭은 양 끝 포함).
  슬라이딩 윈도우로 후보를 찾고 겹치는 구간은 병합한다(맞닿음은 병합하지 않는다).
  기준값 14일/5경기는 파라미터다.
- 이 정의가 기준이며 백엔드 계산이 이 문서를 따른다. 백엔드 기존 계산과 일치함을
  검산으로 확인했다 — 근거와 기각안은 `decisions.md` 2026-08-20 항목.
- 진단 화면과 공유하는 계약이다. 승인 후 `domain.md` 승격 대상이다(승격은 사람이 한다).
- 밀집도 계산은 백엔드 단일 계층에서만 한다. 프론트는 재계산하지 않는다(기존 계약).
- 밀집 구간 판정·강조는 치른 경기에만 적용한다. 미래(예정) 경기 사이의 간격은
  밀집 구간으로 판정하지 않는다.
- 밀집 구간의 시각적 표현 방식은 `[미정]`이다.

### 4. 보기 전환 — 리그만 / 전 대회

- 「리그만 보기 / 전 대회 보기」 전환을 제공한다. 기본은 전 대회 보기다.
- "리그"는 그 팀의 자국 리그 경기를 뜻한다. 컵·유럽대항전은 제외한다.
- 리그만 보기의 수치(분모·간격 중앙값·밀집 구간 수)와 강조 구간은
  **리그 경기만으로 다시 판정한 값**이다. 이 값도 백엔드가 계산해 내려준다.
- 헤더의 분모·간격 중앙값·밀집 구간 수는 보기 기준을 따라 전환된다.
- 리그만 보기에서 진단 문장은 표시하지 않는다. 숨긴 자리에
  `진단은 전 대회 기준으로만 제공됩니다` 라벨을 둔다. 리그 기준 진단 재계산은 제공하지 않는다.
- 토글 상태는 URL에 기록하고, 공유·새로고침 시 복원한다. 구체적인 URL 형식은
  IN-OQ-08에서 토글 상태를 포함해 정한다(`[미정]`).
- 컵 경기만 존재하는 경우(입력 화면 4절의 방어 동작) 리그만 보기는
  `이 시즌 자국 리그 경기가 없습니다` 빈 상태를 표시한다.

### 5. 경기 표시

- 경기마다 결과(승무패·스코어)와 대회 종류를 구분해 표시한다.
- 미확정 경기의 결과·스코어 null, 승부차기 무승부 집계(+`shootout` 별도), H/A만 지원 등은
  기존 응답 계약을 따른다.
- 경기 마커에는 결장 인원수만 표시한다. 결장 데이터가 없는 경기의 null≠0 구분은
  기존 계약을 따른다.
- 경기를 선택하면 그 경기의 결장 명단과 사유 갈래를 표시한다.
  그 외의 경기 상세 정보 노출은 범위 밖이다.

### 6. 진단 문장

- 전 대회 보기에서 규칙 기반 진단 문장을 표시한다.
- AI 분석 층(`/diagnosis`)은 이 화면에서 호출하지 않는다. AI 층은 진단 화면의 범위다.

### 7. 뉴스

- 뉴스 얹기는 기존 계약을 따른다: 각 경기 직전 구간 배치, 마지막 경기로부터
  14일(`TRAIL_OUT_DAYS`) 상한, coverage 4상태 구분, 무채색·점선 표현.

### 8. 데이터 구멍과 분모

- 구멍은 두 종류로 구분한다.
- **경기 자체의 부재** — 판정 단위는 **대회**다. 백엔드는 존재하지 않는 경기를 개별적으로
  알 수 없고, (대회, 시즌) 단위 동기화 이력으로만 안다. `수집 대기중` 표시는 경기 단위
  마커가 아니라 대회 단위 표시다. 예: `유럽대항전 일정은 아직 수집 전입니다`.
- **경기에 붙는 데이터(결장 등)의 부재** — 경기 위치는 아나, 0건이 not-collected인지
  quiet인지는 해당 데이터의 수집 이력과 대조해 가른다. 기존 상태 어휘
  (not-collected / quiet)를 그대로 따른다.
- 두 경우 모두 판정의 진실 공급원은 동기화 이력이다. 화면은 이력이 보장하는 수준까지만
  말한다 — 이력이 대회 단위면 표시도 대회 단위다.
- 동기화 이력은 (대상, 시즌)별 최종 수집 시각을 유도할 수 있는 형태로 이미 기록되고
  있다 — 스키마 변경은 불필요하다. **(대상, 시즌) 단위 조회 쿼리 추가와 타임라인 응답
  노출**이 이번 범위에 포함된다.
- 타임라인의 분모(전체 N경기 중 M경기 표시)는 화면 위쪽 헤더에 표시한다.

### 9. 이번 범위 밖

- AI 분석 층 호출(진단 화면의 범위)
- 예측 입력·적중 표시 UI
- 경기 선택 시 결장 명단·사유 갈래 외의 상세 정보
- 리그 기준 진단 문장 재계산

### 10. 미정

- 밀집 구간의 시각적 표현 방식 (TL-OQ-16)
- 미래 경기 구간의 시각적 표현 (TL-OQ-17)
- 모바일 대응 수준 (TL-OQ-18)
- 구간 확대·이동 상호작용의 제공 여부와 방식 (TL-OQ-19)
- 타임라인 로딩·실패 상태의 화면 표현 (TL-OQ-20)
- "수집 전" 안내에 싣는 대회의 범위 (TL-OQ-21, 2026-08-22 구현 중 발견)

## 미정 집계

### BLOCKER

없음.

### LATER

입력 화면:

1. 답변 불가 상태별 최종 문구
2. 로딩·실패 상태의 구체적인 화면 표현
3. URL의 구체적인 경로와 파라미터 형식 (통합 타임라인의 토글 상태 포함)
4. 이전 시즌 회고록의 상세 내용

통합 타임라인:

5. 밀집 구간의 시각적 표현 방식
6. 미래 경기 구간의 시각적 표현
7. 모바일 대응 수준
8. 구간 확대·이동 상호작용의 제공 여부와 방식
9. 타임라인 로딩·실패 상태의 화면 표현
10. "수집 전" 안내에 싣는 대회의 범위

```text
BLOCKER  0건  ← 0이 되기 전에는 구현을 시작할 수 없다
LATER    10건
```

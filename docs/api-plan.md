# API-Football 플랜 경계 — 무엇이 되고 무엇이 막혔나

*2026-08-04 정리. 무료 플랜(하루 100요청)으로 확인한 것과 못 한 것, 그리고 Pro 전환 후
할 일. 코드 주석의 "CLAUDE.md 상단 체크리스트"는 이 문서를 가리킨다.*

---

## 한 줄 요약

무료 플랜은 **과거 시즌의 "시즌 단위" 조회**만 준다. 시즌 전체를 1요청에 주므로 예산은
오히려 넉넉한데, **현재 시즌이 막혀 있다.** 이 앱이 파는 "다음 경기 예측"은 미래 경기가
있어야 성립하므로, **예측 화면만은 무료로 완성할 수 없다.** 나머지 넷은 과거 시즌으로
끝까지 만들 수 있다.

---

## 1. 무료로 되는 것 — 실제 응답으로 확인됨

근거는 전부 `backend/src/test/resources/apifootball/` 의 캡처 파일이다(무료 키로 실제
호출해 받은 원본). 추측이 아니라 파일이 있다.

| 엔드포인트 | 파라미터 | 받은 것 | 근거 파일 |
| --- | --- | --- | --- |
| `/fixtures` | `league` + `season` | 시즌 전체 **1요청** — PL 2023 380건, FA컵 879건, CL 214건, EFL컵 93건 | `fixtures-league{39,45,2,48}-season2023.json` |
| `/standings` | `league` + `season` | 표 1개(호출 시점 기준) | `standings-league39-season2023.json` |
| `/injuries` | `team` + `season` | 맨유 2023 결장 346건 | `injuries-team33-season2023.json` |
| `/players` | `team` + `season` + `page` | **60명**(20명 × 3페이지) — 대회별 출전·선발·득점 포함 | `players-team33-season2023-page{1,2,3}.json` |
| `/leagues` | `season` | 940개 대회. 시드 id 검증용 | `leagues-raw.json` |

**시즌 범위:** 2022~2024 접근 가능(사용자 확인). 파일로 남아 있는 건 2023뿐이다 —
`*-season2024.json` 두 개는 **API 응답이 아니라 파이프라인 갈래(NS·2H·PST·PEN·경기장
null)를 태우려고 손으로 만든 표본**이므로 플랜 근거로 쓰지 말 것.

## 2. 무료로 막힌 것 — 에러 원문

### 확인됨 (파일에 남아 있음)

**과거 시즌 하한** — `/fixtures?league=39&season=2019`
```
{"plan": "Free plans do not have access to this season, please consider upgrading your plan."}
```
HTTP **200** 에 `errors` 가 실려 온다. 상태 코드만 보면 성공으로 읽힌다
(`fixtures-league39-season2019.json`).

**`/players` 페이지 상한** — `page=4`
```
{"plan": "Free plans are limited to a maximum value of 3 for the Page parameter"}
```
→ **팀당 60명이 상한이다.** 맨유 2023 스쿼드는 60명에서 잘린 것이지 60명이 전부인 게
아니다. (CLAUDE.md 에 "page4 는 0명이라 실제 데이터는 3페이지"라고 적혀 있었는데 사실이
아니었다 — 고쳤다.) 1군 로테이션 판단에는 60명이면 대체로 충분하지만, **"이 팀 선수
전부"라고 말하면 안 된다.**

### 사용자 확인 — 파일 미보관

| 막힌 것 | 영향 |
| --- | --- |
| **현재 시즌**(2025/2026) | 미래 경기가 없다 → **예측을 걸 수 없다.** 이게 가장 아픈 제약 |
| **`last` 파라미터**(최근 N경기) | 대안이 있다 — 시즌 단위로 받아 우리 DB에서 자르면 된다. 실질 영향 없음 |
| **`/fixtures/lineups`**(라인업) | 포메이션·선발 명단을 못 받는다. **결제해도 리그마다 커버리지가 다르다** |

## 3. 아직 확인 안 한 것 — 각 1요청

리그 단위 조회가 되면 팀 단위 108요청이 대회당 1요청으로 줄어든다. 무료 플랜에서
결장 스케줄러를 못 만든 이유가 정확히 이것이다.

```bash
# 결장을 리그 단위로 받을 수 있나
curl -s -H "x-apisports-key: $API_FOOTBALL_KEY" \
  "https://v3.football.api-sports.io/injuries?league=39&season=2023" | head -c 300

# 선수 스탯을 리그 단위로 받을 수 있나 (되더라도 page 3 상한은 그대로일 것)
curl -s -H "x-apisports-key: $API_FOOTBALL_KEY" \
  "https://v3.football.api-sports.io/players?league=39&season=2023&page=1" | head -c 300

# 날짜 범위 조회 (되면 "최근 N경기"를 서버에서 자를 수 있다)
curl -s -H "x-apisports-key: $API_FOOTBALL_KEY" \
  "https://v3.football.api-sports.io/fixtures?league=39&season=2023&from=2023-12-01&to=2023-12-31" | head -c 300
```

**확인하면 이 문서에 결과를 적을 것.** 세 줄이면 되고, 안 적으면 다음에 또 찌른다.

## 4. 무료 플랜으로 어디까지 만들 수 있나

화면별 상세는 [screen-status.md](screen-status.md).

| | 무료로 완성 가능? | 이유 |
| --- | --- | --- |
| 입력(대화) | **가능** | API-Football 과 무관하다. 팀 선택은 DB에 이미 있고, 자유 입력은 Anthropic 쪽 |
| 타임라인 | **거의 가능** | 과거 시즌 일정은 완전하다. "다가올 일정"·뉴스 시간축 겹침만 못 본다 |
| 진단 | **가능** | 지표 6개 전부 과거 시즌으로 계산된다. 결장의 '무게'도 `/players` 로 가능(60명 상한) |
| 예측 | **불가능** | 미래 경기가 없다. 킥오프 이전 규칙 위에 선 앱이라 우회 방법도 없다 |
| 순위표 | **가능** | 과거 시즌은 최종 순위표를 준다 |

**따라서 개막 전 남은 기간에 할 수 있는 일이 예측 하나 빼고 전부 있다.** "유료 전환까지
화면을 손대지 않는다"는 원래 판단은 과했다 — 손댈 수 없는 건 예측 하나다.

## 5. 🚩 2026-08-21 (26/27 시즌 개막) — Pro 전환 시점에 할 일

### 커버 범위 (확정)

유럽 5대 리그 + K리그1, **1부만**. 각 자국컵과 유럽대항전 3개를 함께 받는다 —
컵·유럽대항전이 빠지면 일정 밀집이 실제보다 헐거워 보이고, 그게 이 앱이 진단하려는
바로 그것이다. 총 **16개 대회 · 108팀**(`seeds/competitions.json`).

리그를 빼거나 넣는 건 시드 파일 한 줄이다. 시드에서 빠진 대회는 `CompetitionSeeder` 가
`displayed=false` 로 내려 동기화 대상에서 제외하고, **행과 경기는 남긴다**.

### 예산 — Pro 로 가면 사라지는 제약

| | 무료(100/일) | Pro |
| --- | ---: | ---: |
| 108팀 전체 초기 적재(라인업·선수 스탯 포함, ~2,500요청) | 37일 | 반나절 |
| 유지 | 49/일 (예산의 60%) | 1% 미만 |

그래서 **백필 대기열·데이터 깊이 티어 같은 건 만들지 않는다.** 전환 시점에
`application.yml` 세 줄만 올린다: `daily-request-budget`(80 → 7000),
`max-competitions-per-run`(6 → 20), `interval-hours`(LEAGUE 24 → 6 등).

`RequestBudget` 자체는 **남긴다.** 유료에도 상한이 있고, 버그로 루프가 도는 날 그걸
잡아 주는 게 이 장치다. 숫자만 바뀐다.

### 결제해도 안 되는 것

- **라인업 커버리지** — 플랜과 별개로 리그마다 있고 없다. 아래 0번에서 1요청으로 확인.
- **동기화 코드** — 라인업·선수 스탯 적재는 아직 없다. 우리가 만들어야 한다.

### 순서

0. **⚠️ 결제 전에 1요청으로 라인업 커버리지를 본다.** (현재 시즌 접근권은 이미 답이
   나왔다 — 무료는 막힌다. 그건 다시 확인할 필요 없다.)
   ```bash
   curl -s -H "x-apisports-key: $API_FOOTBALL_KEY" \
     "https://v3.football.api-sports.io/fixtures/lineups?fixture=<과거경기id>" | head -c 300
   ```

1. **현재 시즌 캡처** — `mode: real` + `capture-dir` 로 한 번 돌린다(대회당 1요청).
   ```bash
   ./gradlew bootRun --args='--spring.profiles.active=local \
     --gak.api-football.mode=real \
     --gak.api-football.capture-dir=src/test/resources/apifootball \
     --gak.sync.max-competitions-per-run=1'
   ```

2. **⚠️ `season-override: 2023` 을 지운다** (`application-local.yml`).
   **이걸 잊는 게 가장 위험하다.** 앱은 정상으로 보이는데 화면에는 몇 년 전 일정만 계속
   나온다 — 아무 에러도 안 뜨므로 눈치채기까지 오래 걸린다.
   확인: `select distinct season from fixture;` 또는 `/api/admin/sync/logs` 의 season 값.

3. **예측·채점을 실제로 돌려 본다.** 미래 경기가 생겨야 예측을 걸 수 있고(지금은 모든
   경기가 과거라 `POST /api/predictions` 가 400), 경기가 끝나면 채점 스케줄러가 매시
   30분에 집어 간다. **예측 입력 UI도 이때 붙인다** — 그전엔 누를 수 없는 버튼이다.

4. **`/teams` 응답도 함께 캡처한다.** 팀 한글명 시드(`team-names-ko.json`)가 지금
   **영문 이름 문자열을 키로** 쓰는데 이름은 언제든 바뀐다(`Bayern Munich` ↔
   `Bayern München`). 팀 id 로 바꾸고 싶지만 대조할 원본이 없어 미뤄 뒀다 — 대회 시드가
   `CompetitionSeedTest` 로 검증되는 것과 같은 장치를 팀에도 붙인다.

5. **결장(부상) 스케줄러를 켠다.** 지금은 수동 실행만 열려 있다. Pro 에서는 팀 단위
   108요청을 그냥 돌려도 예산의 1.5% 다. 리그 단위(`/injuries?league=&season=`)가 되면 더
   싸지니 한 번 찔러 보되(3장), 안 돼도 진행한다.

6. **라인업 적재를 만든다.** Pro 로 새로 가능해지는 건 **라인업뿐이다** —
   선수 스탯(`/players`)은 무료에서도 되므로 개막 전에 만들 수 있다(아래 참고).
   - 라인업: **경기 단위 1요청**, 끝난 경기는 안 바뀌므로 한 번 받으면 영구 유효.
     16개 대회 한 시즌이 ~3,800경기(FA컵 예선 879가 대부분 — **노출 팀이 뛴 경기로 범위를
     자를 것**).
   - **포메이션은 사실이니 저장하되, "전술 변화가 원인"이라고 말하지 않는다.** 관측과
     주장의 경계는 AI 진단에 세 겹을 쌓은 것과 같은 자리다.

7. **뉴스가 타임라인에 실제로 얹히는지 확인한다.** 지금은 두 층의 시간축이 안 겹친다 —
   일정은 2023-24(replay), 소식은 2026이라 화면이 "시점이 다릅니다"라고 말하고 아무것도
   얹지 않는다. **이건 정상 동작이다.** 현재 시즌 일정이 들어오면 저절로 겹친다.
   ```bash
   curl -s localhost:8080/api/teams/33/news | python3 -c \
     "import sys,json;c=json.load(sys.stdin)['coverage'];print('소식',c['from'],'~',c['to'])"
   ```
   **뉴스 수집은 개막을 기다리지 않는다.** RSS 는 과거를 주지 않으므로 지금부터 쌓아야
   개막 시점에 프리시즌·이적설 흐름이 남아 있다. 스케줄러를 끄지 말 것.

8. **실데이터로 먼저 볼 것** — 시즌 진행 중일 때의 "여기까지 치름" 경계선, 폼 스트릭 칩
   개수(기간이 시즌 전체라 최근 10개만 그린다), 예정 경기가 있을 때의 예측 패널.

## 6. 개막을 기다리지 않아도 되는 일 — 선수 스탯

`/players?team=&season=` 은 **무료에서 된다**(과거 시즌, 팀당 3페이지=60명). 지금 우리가
"결장 6.6명"이라고만 말하는 것을 **"주전 몇 명이 빠졌나"** 로 바꿀 재료가 이미 손에
있다는 뜻이다 — 맨유 2023 60명분이 replay 로 확보돼 있다.

이건 `DiagnosisPromptFactory` 의 '갖고 있지 않은 정보' 목록에서 한 줄을 지우는 작업이고,
Pro 전환과 **무관하게** 지금 할 수 있다. 다만 **라인업과 혼동하지 말 것** — 선수 스탯은
"이 선수가 시즌 내내 얼마나 뛰었나"(주전성)를 주고, 라인업은 "이 경기에 누가 나왔나"를
준다. 우리가 원하는 건 전자다.

한계 두 가지를 함께 적어야 한다: **60명 상한**, 그리고 **시즌 총계라 시기별 변화를
못 본다**(9월엔 주전이었다가 12월에 밀린 선수를 구분 못 한다).

# 화면 현황 — 무엇이 되고, 왜 안 되고, 무료로 끝낼 수 있나

*2026-08-04 기준. 로컬 DB(맨유 2023-24 replay)로 실제 확인한 상태다.
플랜 경계는 [api-plan.md](api-plan.md).*

**"안 되는 이유"를 데이터와 구현으로 가르는 게 이 문서의 목적이다.** 둘을 섞어 "준비 중"
이라고 적으면 화면만 붙이면 되는 것처럼 읽히는데, 실제로 막힌 것 대부분은 데이터고
데이터는 우리가 코드로 못 푼다.

## 지금 DB에 있는 것 (근거)

```
fixture   1,566건 (전부 2023 시즌 — 두 시즌 섞임 문제는 해소됐다)
team        805개 (FA컵 예선까지 들어와 비리그 클럽 711개 포함)
standing     20행 (PL 2023 한 표)
absence     346건 (맨유 2023)
player       28명 (결장자에서 파생된 것뿐 — /players 적재는 아직 없다)
news_item    59건 (2026년 기사 — 일정과 시간축이 안 겹친다)
prediction    0건 (미래 경기가 없어 하나도 걸 수 없다)
```

| 화면 | 상태 | 막힌 것의 성격 | 무료로 완성 |
| --- | --- | --- | --- |
| 입력(대화) | 뼈대만 | **구현** | ✅ 가능 |
| 타임라인 | 거의 완성 | 데이터(일부) | 🟡 90% |
| 진단 | 완성에 가까움 | **구현**(선수 스탯) + 데이터(라인업) | 🟡 가능, 라인업 제외 |
| 예측 | 백엔드만 완성 | **데이터** | ❌ 불가능 |
| 순위표 | 완성 | — | ✅ 이미 됨 |

## 1. 입력 — 좌측 대화 패널

### 되는 것
- 가이드 질문 4개(왜 이러냐 / 일정 / 폼 / 다음 경기). **답변 문장의 숫자는 전부 진단
  응답에서 읽는다** — 대화와 화면이 다른 값을 말하지 않는다(`lib/chat/script.ts`).
- 근거의 "보기 →" 를 누르면 타임라인으로 넘어가며 해당 구간이 강조된다.
- 표본이 부족하면 답을 만들지 않고 "판정할 경기가 없다"고 말한다.

### 안 되는 것
| | 원인 | 비고 |
| --- | --- | --- |
| 자유 입력("직접 입력은 준비 중") | **구현** | Anthropic 쪽이라 API-Football 플랜과 무관 |
| 팀 선택 — 맨유(id 33) 하드코딩 | **구현** | `app/page.tsx` 의 `MANCHESTER_UNITED_ID` |
| 질문 4개 고정 | **구현** | 데이터에서 만들지만 종류는 코드에 박혀 있다 |

### 무료로 완성 가능한가 — ✅ 가능
데이터가 이미 다 있다. 다만 **팀 선택을 붙이려면 805개를 걸러야 한다** —
`competition.displayed` 인 대회에 나오는 팀만. 안 걸르면 드롭다운에 8부 리그가 섞인다.

자유 입력은 별개 작업이다. 지금 답변은 "우리가 쓴 문장 틀 + 데이터 값"인데, 자유 입력을
받으면 **모델이 질문을 해석하고 지표를 골라야** 한다 — AI 진단(`/diagnosis`)에 세 겹을
쌓은 것과 같은 문제를 다시 풀어야 하므로 화면 하나 분량의 기획이 필요하다.

## 2. 타임라인 — 통합 일정

### 되는 것
- 리그·컵·유럽대항전을 한 축에 통합. 경기 간격이 여백 픽셀로 보인다(`gapScale`).
- 밀집 구간 앰버 브래킷, 폼 스트릭, 대회 배지, 원정 이동거리.
- 뉴스 층이 경기 사이에 얹힌다 — 무채색·점선으로 확정 수치와 구분(`lib/news/attach.ts`).
- 소식이 비면 **왜 비었는지 네 갈래로 말한다**(수집 전 / 시점 불일치 / 보관 기간 밖 /
  정말 조용함).

### 안 되는 것
| | 원인 | 비고 |
| --- | --- | --- |
| 뉴스가 실제로 얹히지 않음 | **데이터** | 일정 2023-24 · 소식 2026 → `season-mismatch`. **정상 동작이다** |
| "여기까지 치름" 경계선을 못 봄 | **데이터** | 시즌이 통째로 끝나 있어 전부 `inAnalysis` |
| 다가올 일정 구간 | **데이터** | 미래 경기가 없다 |
| 기간 선택 UI | **구현** | `season` 쿼리 파라미터는 열려 있고 UI 만 없다 |

### 무료로 완성 가능한가 — 🟡 90%
과거 시즌 일정은 완전하므로 그리는 것은 다 된다. **못 보는 건 "시즌 진행 중"인 상태의
화면**뿐이다 — 경계선과 예정 경기가 그때만 나타난다. 뉴스 겹침도 현재 시즌이 들어와야
확인된다(RSS 는 과거를 안 준다).

## 3. 진단 — 결론 · 근거 · 모르는 것

### 되는 것
- 지표 6개가 **같은 기간**(최신 시즌의 치른 경기)에서 나온다: 밀집도·간격·폼·상대
  강도·결장·이동거리.
- 경기 시점 순위를 우리가 계산한다. 승점 삭감은 API 순위표와 대조로 잡아낸다
  (2023-24 PL 20팀 중 18팀 일치, 어긋난 둘이 정확히 에버턴 −8 · 포레스트 −4).
- 이동거리 25/27 경기 측정. 결장 346건을 부상/징계/기타로 가른다.
- AI 진단이 결론 문장만 덧칠한다. 표본 부족이면 **아예 부르지 않고**, 빈 껍데기 응답은
  코드가 버린다. 배지는 실제 응답으로만 갈린다.
- **"모르는 것" 블록**이 답하지 못한 것을 스스로 밝힌다.

### 안 되는 것
| | 원인 | 비고 |
| --- | --- | --- |
| "주전 몇 명이 빠졌나" — 결장의 무게 | **구현** | `/players` 는 무료로 되고 replay 도 있는데 **적재 코드가 없다**(player 28명은 결장자 파생) |
| 포메이션·선발 명단 | **데이터** | 라인업은 무료 차단. Pro 로도 리그별 커버리지가 갈린다 |
| 결장 자동 갱신 | **구현+데이터** | 스케줄러 없이 수동 실행만. 리그 단위 조회 여부 미확인 |
| 부상 이력의 시기별 변화 | **데이터** | `/players` 는 시즌 총계만 준다 |

### 무료로 완성 가능한가 — 🟡 라인업만 빼고 가능
**여기가 이번 정리에서 가장 크게 바뀐 판단이다.** "선수 스탯은 Pro 전환 후"라고 적어
뒀지만 `/players` 는 무료로 된다(과거 시즌, 팀당 60명 상한). 즉 **"결장 6.6명"을
"주전 몇 명이 빠졌나"로 바꾸는 작업은 지금 할 수 있다.** 막힌 건 라인업 하나다.

## 4. 예측 — 유일하게 데이터로 막힌 화면

### 되는 것 (전부 백엔드)
- `POST /api/predictions` — **킥오프 이전 검증**(서버 시계로만), 그 팀이 그 경기에 실제로
  뛰는지 검증. 위반 시 400.
- 채점 스케줄러(매시 30분, 멱등). 결과를 모르면 보류한다 — 모르는 것과 틀린 것은 다르다.
- `GET /api/teams/{id}/predictions` — 적중률 집계. **표본 5건 미만이면 비율을 감춘다.**
- 화면: 적중률 헤드라인 · 예측값별 성적 · 기록 목록(킥오프 몇 시간 전에 남겼는지 표시).

### 안 되는 것
| | 원인 | 비고 |
| --- | --- | --- |
| 예측 기록 0건 | **데이터** | 동기화된 경기가 전부 과거. 걸 수 있는 경기가 하나도 없다 |
| 예측 입력 UI | **구현**(단, 지금 만들면 무의미) | 누를 수 없는 버튼이 된다 |
| 적중률 화면 전체 | **데이터** | 예측이 없으니 채점도 집계도 0 |

### 무료로 완성 가능한가 — ❌ 불가능
**무료 플랜은 현재 시즌을 막고, 이 앱은 킥오프 이전에만 예측을 받는다.** 우회하려면
그 규칙을 깨야 하는데 그건 이 앱의 존재 이유다. 개막 + Pro 전환 전까지 이 화면은
"무엇이 있고 무엇이 없나" 목록을 정직하게 보여 주는 상태로 둔다 — 지금 화면이 실제로
그렇게 하고 있고, 그게 맞는 상태다.

## 5. 순위표

### 되는 것
- PL 2023 20팀 표. 승격·강등권을 색 **그리고 글자**로 표시(색만으로 구분하지 않는다).
- 기준 시각을 표 위에 적는다 — 타임라인의 "경기 시점 순위"와 다른 값이라서.
- 팀 id 만으로 리그를 찾아낸다. 없으면 사유를 말한다.

### 안 되는 것
| | 원인 | 비고 |
| --- | --- | --- |
| 컵·유럽대항전 순위 | **설계 판단** | 컵은 표가 없고, 조별 표는 서로 다른 조의 1위를 같은 "1위"로 부르게 된다 |
| 실시간 순위 | **데이터** | `/standings` 는 호출 시점 표만 준다. 과거 시즌은 최종 순위가 온다 |
| 리그 하나만 | **구현** | 그 팀의 가장 최근 리그 경기로 고른다 |

### 무료로 완성 가능한가 — ✅ 이미 됐다
과거 시즌으로도 표가 온전히 온다. 팀이 늘면 대회당 1요청씩만 더 든다.

## 화면을 가로지르는 것

1. **팀 805개** — 팀 선택·검색을 붙일 때 `competition.displayed` 로 걸러야 한다.
   지금은 맨유 고정이라 드러나지 않는다.
2. **`season-override: 2023`** — Pro 전환 때 지워야 한다. 안 지우면 앱은 멀쩡한데 화면엔
   몇 년 전 일정이 나온다([api-plan.md](api-plan.md) 5장 2번).
3. **팀 한글명 시드가 영문 이름을 키로 쓴다** — 이름이 바뀌면 조용히 fallback 된다.
   팀 id 로 바꾸려면 `/teams` 응답이 필요하다.
4. **`calendarSeason` 을 자국 리그 기준으로 고른다** — 브라질 팀이 리베르타도레스를
   함께 뛰면 표기가 한쪽 기준이 된다. 팀 선택을 붙일 때 드러난다.
